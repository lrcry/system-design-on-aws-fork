### P76 — URL fragment character in suggested padding alphabet
- **Priority:** High (reviewer approved)
- **Question:** The English suggests `#` as an additional character for a seven-character short URL identifier. In a URL, `#` introduces the fragment; the fragment is not part of the HTTP request target, so it cannot safely be used unencoded as an ordinary path-identifier character. Will the author replace this example with a path-safe character such as `-`?
- **Status:** Open — English-source correction requested.
- **Reviewer decision:** Record High TBC. Explicit P76 comment overrides the proposed TO-BE example: the approved Chinese translation substitutes `-` for `#`, retaining `_`. The English original is unchanged pending author permission.
- **Relevant source:** Chapter 14 English P76; RFC 3986, Section 3.5, https://www.rfc-editor.org/rfc/rfc3986#section-3.5; RFC 3986, Section 2.3 (unreserved characters), https://www.rfc-editor.org/rfc/rfc3986#section-2.3.
