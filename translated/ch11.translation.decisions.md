# Translation Decisions: ch11 — AWS Compute Services

## General Principles

1. **HTML structure preservation**: All HTML tags, attributes, `id`s, `data-type`s, `data-primary`/`data-secondary`/`data-tertiary` index term attributes, `data-startref` attributes, `href`s, and `class` attributes are preserved verbatim.
2. **Index term anchors**: All `<a contenteditable="false" data-type="indexterm" ...>&nbsp;</a>` anchors are kept unchanged — their `data-primary`, `data-secondary`, `data-tertiary`, `id`, and `data-startref` attributes remain in English because they are machine-readable identifiers.
3. **Cross-references**: All `<a data-type="xref" href="...">` elements are kept unchanged.
4. **Code blocks**: The JSON task definition inside `<pre data-type="programlisting">` is not translated; it contains field names and code values.
5. **Figure `alt` text**: The `alt` attribute on figure images is preserved as-is (auto-generated English text); only the `<figcaption>` visible text is translated.
6. **Service name strategy**: AWS service names follow the pattern used in earlier chapters:
   - First occurrence in each chapter: full Chinese name + English name in parentheses (e.g., "亚马逊弹性计算云（Amazon EC2）")
   - Subsequent occurrences: use the abbreviation or short form (e.g., "EC2")
   - Services with no official Chinese name: keep English name (e.g., "AWS Fargate", "AWS Outposts", "AWS Graviton2", "Amazon SQS", "Amazon DynamoDB", "Amazon Kinesis", "Amazon SNS", "Amazon CloudWatch")
