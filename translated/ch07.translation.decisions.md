# Translation Decisions: ch07 — Containerization, Orchestration, and Deployments

## Glossary Reference

All terms follow `glossary.md` entries 538–597. Key decisions are documented below.

---

## Term-Level Decisions

### Docker, Dockerfile, Docker Hub, Docker CLI
Kept in English. These are proper product names with no established Chinese equivalents. Used universally in Chinese technical communities without translation.

### Kubernetes / K8s
Kept as "Kubernetes" throughout. AWS EKS Chinese documentation uses the English name. No Chinese translation is established or expected by Chinese readers.

### Pod
First occurrence rendered as "Pod（容器组）"; subsequent occurrences use "Pod" alone, following AWS EKS Chinese documentation convention. "容器组" is the official AWS EKS Chinese translation per `https://docs.amazonaws.cn/zh_cn/eks/latest/userguide/kubernetes-concepts.html`.

### control plane → 控制平面
Translated as "控制平面" per official Kubernetes Chinese documentation (kubernetes.io/zh-cn). Note: Some AWS EKS docs use "控制面板" but this appears to be a mistranslation — "面板" means "panel" (a physical/UI board), whereas "平面" means "plane" (architectural layer), which is the correct concept. The broader Chinese Kubernetes community and kubernetes.io official Chinese docs consistently use "控制平面".

### worker node → Worker 节点
Kept the "Worker" prefix in English to match AWS EKS Chinese documentation ("Worker 节点"). Fully Chinese alternative "工作节点" avoided to stay consistent with AWS official usage.

### minion → 从属节点（minion）
Translated as "从属节点（minion）" on first occurrence in the architecture section. The term is mentioned only once in the book and "Minion" is kept in parentheses for recognition.

### hypervisor → 虚拟机监管程序
Translation from `aws.amazon.com/cn/containers/` (AWS official). Note: some Chinese sources use "虚拟机监控程序" but AWS documentation uses "监管程序".

### ReplicaSet, ConfigMap, etcd, kubelet, kube-proxy, Job
Kept in English throughout. Per AWS EKS Chinese documentation, these Kubernetes primitives are not translated. Chinese text around them uses Chinese, but the terms themselves remain English.

### container image / image → 容器镜像 / 镜像
"Container image" → "容器镜像"; standalone "image" in context → "镜像". This follows AWS ECR Chinese documentation.

### container registry → 容器注册表
AWS official translation from `aws.amazon.com/cn/containers/`.

### Amazon ECR → 亚马逊弹性容器注册表（Amazon ECR）
Full Chinese name used on first occurrence; "Amazon ECR" used for subsequent references.

### Amazon ECS → 亚马逊弹性容器服务（Amazon ECS）
Full Chinese name on first occurrence; "Amazon ECS" subsequently.

### Amazon EKS → 亚马逊弹性 Kubernetes 服务（Amazon EKS）
Full Chinese name on first occurrence; "Amazon EKS" subsequently.

### containerization → 容器化
AWS official: `aws.amazon.com/cn/containers/`. Used consistently throughout.

### orchestration → 编排
AWS official: `aws.amazon.com/cn/containers/`. "容器编排" used as the compound term.

### blue-green deployment → 蓝/绿部署
AWS CodeDeploy Chinese documentation uses "蓝/绿部署" (with slash). This is the AWS official form preferred over "蓝绿部署" (without slash).

### canary deployment → 金丝雀部署
AWS CodeDeploy Chinese documentation uses "金丝雀" for canary. Also widely used in Chinese tech community.

### rolling deployment → 滚动部署
AWS official translation from CodeDeploy documentation.

### serverless → 无服务器
AWS Lambda Chinese page uses "无服务器" consistently.

### function as a service (FaaS) → 函数即服务（FaaS）
AWS Lambda Chinese page uses "函数即服务". The abbreviation FaaS is kept in parentheses.

### infrastructure-as-code (IaC) → 基础设施即代码（IaC）
AWS CloudFormation Chinese page uses this exact form. IaC abbreviation retained.

### CI/CD pipeline → CI/CD 流水线
"流水线" is the AWS Chinese documentation standard for "pipeline" in CI/CD context (from `aws.amazon.com/cn/devops/continuous-integration/`).

### continuous integration → 持续集成（CI）
AWS DevOps Chinese documentation. Abbreviation kept in parentheses on first occurrence.

### continuous deployment → 持续部署（CD）
AWS DevOps Chinese documentation. Note: the source text uses "continuous deployment" specifically (not "continuous delivery"). Translated accordingly.

### pull request → 拉取请求（PR）
No AWS official translation. "拉取请求" is the widely accepted Chinese technical community term. "PR" kept in parentheses.

### StatefulSet → StatefulSet 部署
"StatefulSet" kept in English (same convention as ReplicaSet). "部署" added in Chinese for context.

### re-creating deployment → 重建部署
No official translation. "重建部署" is the logical and widely-used Chinese equivalent.

### readiness probe → 就绪探针
Kubernetes standard terminology in Chinese. "就绪探针" is the accepted translation used in Chinese Kubernetes documentation.

### Gitflow → Gitflow
Kept in English. Proper brand/methodology name with no Chinese equivalent.

### DevOps → DevOps
Kept in English. AWS Chinese documentation uses "DevOps" directly (not "开发运维") in technical contexts.

### cloud native → 云原生
AWS EKS Chinese page uses "云原生". This is a well-established Chinese technical term.

### microservice → 微服务
AWS Microservices Chinese page uses "微服务". Standard Chinese technical term.

### base image → 基础镜像
Widely used Chinese term in Docker documentation. "基础层" used for "base layer".

### semantic versioning (SemVer) → 语义化版本（SemVer）
`semver.org/lang/zh-CN/` provides the official Chinese translation.

### Open Container Initiative (OCI) → 开放容器倡议（OCI）
Non-official translation. No AWS official translation found.

### Docker Content Trust (DCT) → Docker 内容信任（DCT）
Non-official translation. Docker's English name kept, "内容信任" for "Content Trust".

### RBAC → 基于角色的访问控制（RBAC）
AWS EKS RBAC Chinese documentation uses this form.

### Docker daemon → Docker 守护进程
Widely accepted Chinese translation. "守护进程" is the standard for "daemon" in Chinese Linux/Unix contexts.

## Structural Decisions

### Code blocks
The Dockerfile example (lines 114–133 in source) is preserved exactly as-is, including English comments. Code is not translated.

### Index terms (`<a data-type="indexterm">`)
All indexterm anchor elements preserved without modification. They are structural markers, not visible text.

### Figure captions
All figure captions translated to Chinese. Image file paths (`src` attributes) unchanged.

### Table
"VMs versus containers" comparison table fully translated including headers and cell content. Technical terms within cells use the same glossary translations.

### Note boxes (`<div data-type="note">`)
Content translated. The note about Amazon EKS cross-reference preserved with the same `xref` ID.

### Hyperlinks
Link text translated where appropriate (e.g., "Kubernetes architecture" → "Kubernetes 架构"). URLs preserved exactly. Link text for code/tool names kept in English (Terraform, Ansible, etc.).

### First-occurrence parenthetical
Key technical terms are introduced with both Chinese and English on first occurrence:
- 虚拟机（VM）
- 虚拟机监管程序（hypervisor）
- Pod（容器组）
- 函数即服务（FaaS）
- 基础设施即代码（IaC）
- 持续集成（CI）
- 持续部署（CD）
- 拉取请求（PR）

Subsequent occurrences use the Chinese name alone (or the English acronym for well-known abbreviations like CI, CD, IaC).
