### P108 — SSE automatic reconnection versus recovery of missed events
- **Source concern:** The text suggests SSE can reestablish connections and recover messages missed during disconnection as a built-in capability.
- **Reason for review:** Automatic reconnection is supported by `EventSource`, but recovering missed events requires appropriate server-side event IDs and replay/retention support.
- **Question for author:** Could automatic reconnection be distinguished from server-assisted replay using `Last-Event-ID`?
- **Translation treatment:** Preserve the original statement pending author response.
- **Priority:** **Medium** (user-confirmed).

### P120 — REST listed among RPC implementations
- **Source concern:** The paragraph lists SOAP, REST, gRPC, and Thrift as RPC examples. The following REST subsection itself says REST is an architectural style.
- **Nuance:** REST-style APIs can invoke remote operations and can expose RPC-like behaviours; this does not make REST as a whole an implementation of the RPC architectural style.
- **Question for author:** Could REST be characterised as a separate resource-oriented architectural paradigm, while acknowledging that RESTful requests can perform remote operations?
- **Translation treatment:** Do not silently recategorise REST.
- **Priority:** **Medium** (user-confirmed after discussion).

### P143 — GraphQL subscription keyword and transport mechanism
- **Source concern:** The text calls `Subscription` a keyword and suggests GraphQL subscriptions inherently establish a bidirectional connection.
- **Reason for review:** GraphQL operation syntax uses lowercase `subscription`; `Subscription` generally names the root schema type. GraphQL subscriptions do not universally require a bidirectional transport and may operate over WebSockets or SSE.
- **Question for author:** Could the keyword/schema-type distinction and non-mandatory bidirectional transport be clarified?
- **Translation treatment:** Preserve source wording pending author response.
- **Priority:** **Medium** (user-confirmed).

### P144 — Did the author mean the AWS AppSync SDK?

- **Nuance:** AWS AppSync is a managed API service, but historically there was an AWS AppSync JavaScript SDK providing Apollo-based client capabilities; the author may have intended that SDK.
- **Question for author:** Did you mean the **AWS AppSync SDK** rather than the **AWS AppSync managed service**? If so, could the SDK be named explicitly?
- **Translation treatment:** Preserve official AWS English product naming and avoid prematurely rewriting the architecture.
- **Priority:** **Medium** (user-confirmed; wording refined after SDK discussion).
