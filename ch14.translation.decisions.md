# Translation Decisions: ch14 — Designing a URL Shortener Service

## Overview
This file records key translation decisions made during the translation of `ch14.html` to Simplified Chinese. It supplements the glossary and explains choices that may not be immediately obvious.

---

## 1. Chapter Title

| English | Chinese | Rationale |
|---------|---------|-----------|
| Designing a URL Shortener Service | 设计短网址服务 | "短网址" is the widely understood Chinese term for a shortened URL. "URL 缩短服务" was considered but "短网址服务" is more natural and concise in Chinese. |

---

## 2. System Design Terms

| English | Chinese | Rationale |
|---------|---------|-----------|
| URL shortener service | 短网址服务 | "短网址" is the standard Chinese term (e.g., Weibo short URL = 微博短网址). "URL 短链服务" was also considered but "短网址服务" is more widely used. |
| functional requirements | 功能性需求 | Standard Chinese CS term. IEEE/ISO standard translation. |
| nonfunctional requirements (NFRs) | 非功能性需求（NFR） | Standard Chinese CS term. Parenthetical "(NFR)" retained for reference. |
| scale | 规模 | In context of "system scale", "规模" is the natural translation. The original sentence "Scale refers to the number of users or the traffic" → "规模是指……用户数量或流量". |
| value-add requirements | 增值需求 | "增值" (value-add/value-added) is the standard business Chinese term. |

## 3. Algorithm & Technical Terms

| English | Chinese | Rationale |
|---------|---------|-----------|
| hashing | 哈希 | "哈希" is the dominant transliteration in Chinese tech. "散列" is the academic/formal translation but "哈希" is far more prevalent in Chinese tech writing. Both mentioned in the glossary. |
| MD5 | MD5（消息摘要算法 5） | Full Chinese expansion used on first mention in glossary; in body text, "MD5" alone is used as it is universally understood. |
| hash collision / collision | 哈希碰撞 | Standard Chinese CS term. "碰撞" literally means collision, consistent with 哈希碰撞 used in Chinese tech documentation. |
| base62 encoding | Base62 编码 | "Base62" kept in Latin; "编码" = encoding. Capitalized as "Base62" to match the standard representation. |
| unique ID generation | 唯一 ID 生成 | "唯一" = unique; "ID" kept in English as it is universally understood; "生成" = generation/generation. |
| key generation service (KGS) | 密钥生成服务（KGS） | "密钥" = key (cryptographic key/ID key). While "密钥" normally means "secret key", in this context it refers to a unique string identifier. The acronym KGS is retained for clarity. |
| Snowflake | Snowflake（雪花算法） | The Chinese tech community has widely adopted "雪花算法" (Snowflake algorithm) for Twitter's ID generation approach. The English "Snowflake" is retained first, with the Chinese equivalent in parentheses. |
| ticket servers | Ticket 服务器 | "Ticket" is kept in English as the Flickr-coined term. "票据服务器" in parentheses in the glossary is explanatory but not used in the translation body. |
| AUTO_INCREMENT | AUTO_INCREMENT | Database keyword; kept as-is in code context. |

## 4. Architecture & Design Patterns

| English | Chinese | Rationale |
|---------|---------|-----------|
| cell-based architecture | 单元式架构 | From the existing glossary entry #219: "单元式架构（Cell-based 架构）". Used consistently. |
| multitenant system | 多租户系统 | Standard term used by AWS China (aws.amazon.com/cn/what-is/multi-tenancy/). |
| physical separation | 物理隔离 | "物理隔离" is the standard Chinese term for physical isolation/separation in distributed systems. |
| virtual (logical) separation | 虚拟隔离（逻辑隔离） | "虚拟隔离" for virtual separation, with "逻辑隔离" as the parenthetical alias per the original "virtual (or logical)". |
| Day 0 architecture | Day 0 架构 | "Day 0" kept in English as it is a well-known AWS paradigm. "初日架构" was mentioned in the glossary as an alternative but "Day 0 架构" is more natural in Chinese AWS documentation. |
| Day N architecture | Day N 架构 | Same rationale as Day 0. |
| Make It Work, Make It Right, Make It Fast | 先让它跑起来，再让它做对，最后让它快起来 | This classic software engineering principle has a widely cited Chinese translation in the Chinese developer community. Kept natural and colloquial. |
| microservice architecture | 微服务架构 | Standard Chinese term, consistent with earlier chapters. |
| monolithic application | 单体应用 | Standard Chinese term. |
| software lifecycle | 软件生命周期 | Standard Chinese term. |
| separation of concern | 职责分离 | "职责分离" is the standard Chinese translation, preferred over "关注点分离" in an operational/architecture context. |

## 8. Notes on Table Translation (Scaling Table)

The table "Scaling from zero to millions of users" was translated with attention to the cause-effect structure:
- "Why" (原因) — explains the motivation for each step
- "How" (方法) — describes the implementation approach
- "Benefits" (收益) — describes the outcome

The column "Step" became "步骤" (step), consistent with the chapter's scaling discussion.
